## Import

```ts
import { createSandbox } from "@elie-laloum/outpost";
```

## Rôle et comportement

Alloue un environnement avec sandboxProvider et le garde ouvert pour enchaîner dispatchs, commandes et sessions de terminal jusqu’à ce que vous le fermiez. Sans workspace, elle en ouvre un que close() ferme aussi, par défaut sur le checkout du répertoire courant avec Docker. Si la préparation échoue, elle libère ce qu’elle a alloué, ferme le workspace qu’elle a ouvert et relance l’erreur.

[Exemple complet et règles détaillées](../../guide/sandbox-sessions/).

## Paramètres et propriétés

### Variante 1 — `FileSandboxOptions`

Les champs ci-dessous couvrent toutes les variantes ; la signature précise leurs combinaisons autorisées.

| Nom                         | Type                                                      | Présence          | Rôle                                                                                                                                                 |
| --------------------------- | --------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `options`                   | `FileSandboxOptions`                                      | Requis            | Workspace à utiliser ou à ouvrir (dépôt, branche, copies), provider, agent par défaut, hooks de préparation et réglages de synchronisation distante. |
| `options.hooks`             | `LifecycleHooks \| undefined`                             | Optionnel         | Commandes de préparation déclarées workspaceReady, hostReady et sandboxReady.                                                                        |
| `options.limits`            | `Pick<StageLimits, "copyMs" \| "collectMs"> \| undefined` | Optionnel         | Délais de copie et de collecte pour l’exécution de fichiers ; les délais de préparation Git et d’intégration sont refusés.                           |
| `options.observation`       | `ObservationHub \| undefined`                             | Optionnel         | Hub d’observation explicite conservant la livraison contextualisée et la comptabilité synchrone d’usage.                                             |
| `options.logging`           | `Logging \| undefined`                                    | Optionnel         | Journal d’exécution déclaré ; les effets de fichiers replayables sont refusés lorsque leur reproduction n’est pas prise en charge.                   |
| `options.activityTransport` | `Transport \| undefined`                                  | Optionnel         | Transport des observations bornées d’activité de ressource ; la vivacité n’autorise pas la récupération.                                             |
| `options.recoveryTransport` | `Transport \| undefined`                                  | Optionnel         | Transport explicite conservant les preuves de récupération de sandbox indépendamment des snapshots de fichiers.                                      |
| `options.sandboxProvider`   | `SandboxProvider`                                         | Requis            | Provider d’exécution disposant de la capacité de liaison de fichiers requise ; les providers legacy restent utilisables pour Git.                    |
| `options.agent`             | `DispatchAgent \| undefined`                              | Optionnel         | Agent explicitement composé compatible avec les capacités d’exécution de fichiers et de conversation sélectionnées.                                  |
| `options.signal`            | `AbortSignal \| undefined`                                | Optionnel         | Signal d’annulation transmis à l’opération et à son groupe de processus ; les sandboxes réutilisables restent utilisables.                           |
| `options.variables`         | `Readonly<Record<string, string>> \| undefined`           | Optionnel         | Seules les variables d’environnement explicitement déclarées atteignent la sandbox ; aucun chargement implicite de .env.                             |
| `options.workspace`         | `FileWorkspace \| undefined`                              | Selon la variante | Workspace ouvert emprunté pour cette opération ; son caller reste responsable de sa fermeture.                                                       |
| `options.workspaceSource`   | `undefined \| FileWorkspaceSource`                        | Selon la variante | Source déclarée pour une ressource possédée ; exclusive de l’emprunt d’un workspace ouvert.                                                          |
| `options.recovery`          | `FileWorkspaceRecoveryAuthorization \| undefined`         | Selon la variante | Autorisation explicite de récupération après arrêt des processus ; le replay interrompu reste une décision distincte du workflow.                    |
| `options.storageQuota`      | `Omit<StorageReservationOptions, "signal"> \| undefined`  | Selon la variante | Réservation d’admission via Transport ; coordonne les writers coopérants sans imposer de quota physique de disque.                                   |
| `options.inputs`            | `readonly WorkspaceInput[] \| undefined`                  | Selon la variante | Entrées de fichiers explicites ; les paramètres JSON du workflow ne sont jamais écrits implicitement sur disque.                                     |
| `options.runtime`           | `WorkspaceRuntimeOptions \| undefined`                    | Selon la variante | Répertoire de contrôle et namespace logique, séparés des fichiers du workspace.                                                                      |
| `options.paths`             | `readonly string[] \| undefined`                          | Selon la variante | Sélection explicite de chemins relatifs ; la sélection de copie n’applique pas implicitement .gitignore.                                             |
| `options.retention`         | `WorkspaceRetention \| undefined`                         | Selon la variante | run nettoie le travail possédé réussi, local le conserve, portable exige en plus un Transport et un namespace explicites.                            |
