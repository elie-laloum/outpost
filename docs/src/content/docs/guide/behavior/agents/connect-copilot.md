`agent({ harness: copilotHarness() })` runs GitHub Copilot CLI, `copilot`, through the same sandbox providers as the other adapters. Every run starts a fresh session, and requests count against the premium requests of your GitHub Copilot plan.

## Install the CLI

Images generated by `outpost init` install the pinned `@github/copilot` package alongside Claude Code, Codex and Kimi Code. Remote providers bootstrap the same pinned version into `~/.outpost-tools` when needed, unless `bootstrap: false`. For `localSandboxProvider()`, install `@github/copilot` on the host yourself. `agentVersions.copilot` reports the pinned reference version.

Outpost sets `COPILOT_AUTO_UPDATE=false` for every `copilot` command so that the CLI does not replace itself during a run. A value in the harness `variables` overrides it.

## Authenticate

Select authentication explicitly with the harness `authentication` option. Without it, Outpost prepares nothing and `copilot` uses whatever the sandbox environment already provides. Copilot accepts `account`, `account.file`, `account.key` and `account.variable`. See the [authentication manual](../../../manual/authentication/) for the forms shared by all agents and GitHub's [Copilot CLI authentication](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli) for token types.

### Host login

```ts
import { agent as composeAgent, copilotHarness } from "@elie-laloum/outpost";

const login = composeAgent({
  harness: copilotHarness({ authentication: "account" }),
});
const dedicated = composeAgent({
  harness: copilotHarness({
    authentication: { account: { file: "~/.outpost/accounts/copilot.json" } },
  }),
});
console.log(login.name, dedicated.name);
```

Run `copilot login` on the host. `account` reads `config.json` in `COPILOT_HOME`, otherwise `~/.copilot`; `account.file` reads another file of the same format. Comments and trailing commas are accepted. Outpost extracts only the token stored in `authTokens` for the `lastLoggedInUser` host and login, then passes it to every `copilot` command as `COPILOT_GITHUB_TOKEN`; no file is copied into the sandbox. This works with Docker, Podman, Vercel, Daytona and Firecracker. Outpost reads only regular files of at most 1 MiB; symbolic links and directories are refused, and file contents never appear in errors.

Copilot stores its token in the system keychain by default and writes it to `config.json` in plain text only when no keychain is available or when `storeTokenPlaintext` is `true`. Outpost never reads a system keychain. When `config.json` holds no token for the last signed-in user, preparation fails and asks you to pass `{ account: { variable: "COPILOT_GITHUB_TOKEN" } }` instead.

With `localSandboxProvider()`, Outpost reads no host file: `copilot` uses its own host login for `account` and `account.file`, including a keychain login that the CLI reads itself.

### GitHub token

```ts
import { agent as composeAgent, copilotHarness } from "@elie-laloum/outpost";

const declared = composeAgent({
  harness: copilotHarness({
    authentication: { account: { variable: "COPILOT_GITHUB_TOKEN" } },
  }),
});
const team = composeAgent({
  harness: copilotHarness({
    authentication: { account: { variable: "TEAM_COPILOT_TOKEN" } },
  }),
});
console.log(declared.name, team.name);
```

`account.variable` reads the named variable from the resolved workflow variables: the harness `variables`, the sandbox provider `variables` and the declarations in the repository `.outpost/.env`. `account.key` takes a literal token, which should stay out of committed code. In both cases, Outpost passes the token as `COPILOT_GITHUB_TOKEN`, which Copilot checks before `GH_TOKEN` and `GITHUB_TOKEN`. A missing variable fails when the sandbox is prepared with `Missing TEAM_COPILOT_TOKEN. Declare the selected credential explicitly.` On the local provider, this variable is forwarded and overrides the host login.

Use a fine-grained personal access token with the **Copilot Requests** permission, or an OAuth token (`gho_` or `ghu_`). Copilot CLI does not support classic personal access tokens: Outpost rejects a `ghp_` token when the agent is composed for `account.key`, and when the sandbox is prepared for `account.variable` or a token read from `config.json`.

### Unsupported forms and token lifetime

Copilot has no API-key billing, so `"usage"`, `{ usage: { key } }` and `{ usage: { variable } }` fail when the agent is composed: `GitHub Copilot CLI does not support usage authentication. Accepted forms: account, account.file, account.key, account.variable`. Invalid shapes, empty values and invalid variable names fail the same way.

`account` passes the host's current OAuth token; no refresh token is copied. When you sign out on the host or the token is revoked, sandboxes using it fail as well. For long-running automation, prefer a fine-grained personal access token dedicated to Outpost, which you can rotate and revoke independently of your interactive login.

## Configure execution

```ts
import {
  agent as composeAgent,
  copilotHarness,
  dispatch,
} from "@elie-laloum/outpost";
import { dockerSandboxProvider } from "@elie-laloum/outpost/providers/docker";

const token = process.env.COPILOT_GITHUB_TOKEN;
if (!token)
  throw new Error("Supply COPILOT_GITHUB_TOKEN before running this workflow");
const result = await dispatch({
  repository: "/path/to/repository",
  agent: composeAgent({
    harness: copilotHarness({
      authentication: { account: { variable: "COPILOT_GITHUB_TOKEN" } },
      variables: { COPILOT_GITHUB_TOKEN: token },
    }),
  }),
  sandboxProvider: dockerSandboxProvider(),
  branch: { mode: "named", name: "copilot-review" },
  brief: { text: "Review the repository and report your findings." },
});
console.log(result.text);
```

Build the generated image before this example. `model` on `agent()` accepts a model name available to your Copilot plan and is passed with `--model`; `reasoning` and `maxOutputTokens` are rejected when the agent is composed.

A headless run executes the following command, with the prompt on stdin:

```sh
copilot [--model MODEL] --output-format json --allow-all --no-ask-user
```

`--allow-all` allows every tool, path and URL inside the selected sandbox, and `--no-ask-user` prevents questions that would wait for terminal input. Only select repositories whose project configuration you trust. Outpost's provider supplies isolation; `localSandboxProvider()` remains unisolated.

Interactive sessions run `copilot [--model MODEL] [--interactive TEXT]` in the CLI terminal interface, where Copilot asks for its usual approvals. They require a provider with interactive terminal support, such as Docker, Podman or local execution. See [interactive sessions](../../../environment/commands/).

## Output and failures

Events are decoded by their `type` field. `assistant.message` records become text observations from `data.content` and tool observations from `data.toolRequests`, with `name`, `arguments` and `toolCallId`. `session.error` records become nonfatal warnings. Other records remain available in raw observations.

The final `result` record reports the session ID and decides the outcome: it succeeds with `exitCode: 0`, and fails with any other exit code or with `outcome: "blocked"`. A nonzero CLI exit also fails the dispatch. A final result is required: a zero exit without one fails, so truncated output cannot silently succeed.

## Usage and session limits

Copilot bills premium requests on your GitHub plan, not tokens, and its output reports no token counts: `result.usage` stays at zero. Track consumption in your GitHub Copilot settings.

Copilot sessions are fresh sessions only. The emitted session ID is informational: Outpost does not capture, relocate, restore, resume or fork Copilot conversations. `result.resume()`, `result.fork()` and explicit continuations fail with `GitHub Copilot CLI does not support continuation or fork in Outpost`, including within a warm sandbox. Additional passes start fresh sessions. Structured responses work with `repairs: 0`; automatic repair requires continuation and is rejected. Session resume is planned; see the [roadmap](../../../../project/roadmap/).

## Diagnose the installation

Inspect the installed CLI without model calls or credentials:

```sh
npx @elie-laloum/outpost doctor --sandbox-provider docker --agent copilot
```

The check runs `copilot --version`, reported next to the pinned reference version, and `copilot --help`, which must identify the command and declare the options Outpost uses. It does not authenticate an account or prove a live model's behavior.
