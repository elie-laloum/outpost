# Product

## Platform

web

## Users

TypeScript developers evaluating whether to adopt Outpost to run coding agents from their own code. They arrive from the npm package, the GitHub mirror or a search, usually with a concrete need: run Claude Code, Codex or another agent against a real Git repository, in an environment they control, as part of a larger program or pipeline. They judge quickly whether the API is sound, whether the execution and security boundaries are honest, and whether they can get a first request working. Once adopted, the same developers return to the Guide for a capability and to the Reference for exact contracts.

The maintainer is currently the only production user. Design decisions still target the outside evaluator first.

## Product Purpose

Outpost is a TypeScript library and CLI (`@elie-laloum/outpost`, MIT) for running coding agents in reusable sandboxes, managing their Git workspaces, preserving their conversations and composing typed workflows. Success on the web surfaces means an evaluating developer understands what Outpost is and how it differs within a minute, reaches a working first request through Setup, and can then find any capability or exact API contract without friction, in English or French.

## Positioning

In order of emphasis:

1. **Code orchestrates, agents think.** LLM pipelines hand the model everything: certain steps, order, context and recovery. Outpost keeps order, checks, branch handling and resume in typed TypeScript and gives an agent only the work that needs judgment, from its own brief, in its own sandbox. The home page leads with the capability and the API; the thesis follows in the lead, and the pains this removes are the page’s second movement: everything interpreted, growing context, orchestrator drift, resume as re-interpretation.
2. **Agent × sandbox independence.** Claude Code, Codex, Antigravity, GitHub Copilot CLI, Kimi Code and Outpost's own built-in harness run on Docker, Podman, Vercel, Daytona or explicit host execution, behind stable ports, from one TypeScript API.
3. **Explicit ownership.** The developer owns the environment, credentials, Git workspace and recoverable state. Authentication is chosen explicitly per harness, nothing silently falls back to the host, and recovery artifacts are preserved rather than discarded.
4. **Typed durable workflows.** Agent runs become typed tasks with dependencies, checkpoints, gates, caches, replay, quota pauses and resumable conversations, rather than one-shot chat calls.

## Operating Context

- The documentation site in `docs/` is the web presence: Astro Starlight with the `starlight-theme-celestia` plugin, custom components in `docs/src/components/` and styles in `docs/src/styles/custom.css`. It is deployed to GitHub Pages at <https://elie-laloum.github.io/outpost/> only after a successful stable release.
- Two navigation spaces: **Guide** (practical learning by concept and integration, short snippets) and **Reference** (generated symbol pages with a bilingual Overview per family, custom icons per symbol kind).
- English is the default locale; French mirrors every page under `fr/` with matching paths.
- The docs home page (`docs/src/content/docs/index.md` and its French counterpart) is the planned landing page, inside the same Starlight site. No separate marketing site is planned.
- Evaluators typically read with a terminal and editor open, copy snippets and follow links to GitLab (canonical), GitHub (mirror, CI) and npm.

## Capabilities and Constraints

- Docs stay on Astro Starlight; no framework replacement.
- Guide snippets are typechecked against the package and selected ones are executed; Reference pages and both changelogs are generated by `docs/scripts/sync-reference.mjs`. Design changes must not hand-edit generated output.
- Existing symbol URLs and redirected guide routes must keep working (`docs/audit/guide-redirects.json`).
- Documentation checks cover language parity, links, generated references, rendered output, search, examples and browser tests (`npm run docs:check`, `docs:build`, `docs:test`, `docs:test:browser`).
- Firecracker and speculation are experimental; experimental symbols carry a localized warning and a flask icon. Released, unreleased and research capabilities must remain distinguishable.
- Current package version: 8.0.0 (read `package.json` rather than trusting this line).

## Brand Commitments

- Name: **Outpost**.
- Headline (2026-10-01): “Run coding agents from your TypeScript.” (FR « Exécutez des agents de code en TypeScript. »).
- Tagline, kept in the landing footer: “Run an agent, own its environment, compose a workflow.”
- Voice: direct, precise and factual; states boundaries and limitations plainly; never promises zero side effects or implies unreleased capabilities have shipped.
- English/French parity for all user-facing content.

## Evidence on Hand

- Real, typechecked code snippets from the Guide and README.
- The supported agents and sandbox providers listed above; OpenAI and Anthropic model providers for the built-in harness.
- MIT license (`LICENSE`), security boundaries (`SECURITY.md`), changelog (`CHANGELOG.md`) and public roadmap (`docs/src/content/docs/project/roadmap.md`).
- Engineering rigor that can be stated factually: CI on Windows, macOS and Linux, real Docker/Podman tests, package smoke tests, an 80% coverage floor, npm provenance.
- Custom reference icons in `docs/src/assets/`. The Outpost logo, a warehouse glyph on a transparent background, is `docs/src/assets/outpost-logo.png`; `outpost-mark.png` is its trimmed display copy.

There are no users, customers, testimonials, logos, adoption figures or benchmarks. Never fabricate them.

## Product Principles

1. **Honesty over hype.** State boundaries, experimental status and limitations as clearly as capabilities.
2. **Show the code.** Real, working API usage is the primary proof.
3. **Explicit beats magic.** Ownership, authentication and failure behavior are always visible to the reader.
4. **Evaluator first, reference forever.** Orient a newcomer fast, then serve precise lookup for the long run.
5. **Two languages, one product.** French is a peer of English, not a translation afterthought.

## Accessibility & Inclusion
