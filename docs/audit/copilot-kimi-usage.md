# Copilot and Kimi token accounting

Protocol inspection targets the pinned packages in `src/providers/versions.constants.ts`:

- [`@github/copilot` 1.0.88](https://registry.npmjs.org/@github/copilot/1.0.88) and its Linux binary; the [official Copilot event schema](https://github.com/github/copilot-sdk/blob/main/nodejs/src/generated/session-events.ts) describes `assistant.usage` and `session.shutdown.data.modelMetrics.*.usage`. The [upstream JSON-output issue](https://github.com/github/copilot-cli/issues/4107) records the absence of token counters in the CLI's final `result` event. `premiumRequests` is never interpreted as tokens.
- [`@moonshot-ai/kimi-code` 2.1.1](https://registry.npmjs.org/@moonshot-ai/kimi-code/2.1.1), specifically the bundled `PromptJsonWriter`, `UsageRecord`, `UsageAgentModel`, session addressing and wire reader implementations in `dist/main.mjs`. This is the JavaScript CLI installed by Outpost, not the older Python Kimi wire protocol. It writes additive `usage.record` entries in each agent's `wire.jsonl` and omits them from prompt-mode JSON output.

Only selected numeric fields leave the sandbox reader. It does not capture transcripts or enable continuation. The reader accepts one simple session identifier, rejects linked descendants, canonicalizes the configured CLI home, and limits bytes, records, directories, agents, retained output and command duration. Missing, malformed, truncated or oversized data is incomplete, never an inferred free run. Kimi aggregates the main agent and child agents without counting step-end or context summaries again. Copilot reconciles cumulative totals with streamed deltas.

For adapters using session accounting on continuation, a pre-command baseline excludes historical tokens. An unreadable baseline or a fork whose inherited total cannot be established makes session accounting incomplete; inherited totals are not charged to the new invocation. Streaming deltas remain observable.

The tests use recorded protocol shapes and synthetic session files. `test/unit/agent-usage.test.ts` exercises the actual reader command with local files. `test/functional/agent-usage.test.ts` covers real child processes, failure, cancellation, reuse, workflow budgets, speculation and checkpoint replay. `test/container.test.ts` runs both readers in a container's private home with networking disabled. These checks do not establish authenticated compatibility or reconcile provider billing; those remain live-campaign work.
