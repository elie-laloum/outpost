# YAML recipes

Read this brief before changing `src/application/recipes/`, `src/domain/recipes/`, `recipes/`, the recipe CLI commands in `src/cli/` or `scripts/recipe-*.mjs`. `src/AGENTS.md` and the root `AGENTS.md` still apply.

Local YAML recipes use `defineRecipe(source, { sandbox, agents, inputs })` to compile sequential command and agent steps into existing workflow tasks. The engine borrows the sandbox; its caller owns integration and cleanup. Format 1 keeps strings literal; format 2 declares typed scalar inputs and single-pass references to direct dependency outputs. The primary CLI flow uses two separate YAML files: shared recipe and required local execution configuration (repository, sandbox, composed agent roles, explicit authentication and selected environment names). Configuration paths resolve from its directory. `recipe init` creates starters and editor schema links; `recipe validate` checks without allocation or resolving secrets; `recipe run` validates inputs and agent roles before allocation, integrates according to branch policy and emits a bounded report after cleanup only when requested. TypeScript configurations and legacy factories remain supported. `recipes/` owns the official bundled catalogue; regenerate it with `node scripts/recipe-catalog.mjs --write`. Third-party catalogues use local JSON or HTTPS. `recipe fetch` verifies bounded bytes, SHA-256 and recipe identity before exclusive creation, never execution. Digests provide integrity against the selected catalogue, not publisher authentication.

Recipe compilation normalizes validated documents and resolved components into one internal discriminated union, then delegates each operation to a typed compiler. Keep the parsed document unchanged for project/checkpoint identity and public compatibility. Preserve each source version's text rules, native results in formats 1/2 versus JSON projections in format 3, concurrency defaults and lazy sandbox ownership. Never serialize the normalized runtime representation into checkpoints. Expressions and conditions compile once into located nodes (`compileRecipeExpression()`, `compileRecipeCondition()`) shared by validation and evaluation; keep format 1 literal, single-pass interpolation and direct-dependency references. Execution configurations follow the same rule: per-version read adapters in `recipes/configuration-model.ts` produce one `RecipeConfigurationModel` (component declarations, Git or file workspace, agent roles, declared environment names), and the original document remains the identity source.

Recipe format 3 also composes structured JSON inputs, result projections, conditions, local callbacks, loops, decisions and isolated multi-repository tasks through the existing scheduler. Refuse concurrent use of one shared workspace and leave borrowed workspaces open. Durable recipes retain original workspace records and guards, refuse missing worktrees, and use native checkpoints, caches, artifacts, gates and dialogues. Resume by run ID; interrupted replay and checkpoint-owner recovery require explicit authorization. YAML queues, jobs, cron schedules and authenticated webhook sources compose existing engines. Services start only through `recipe serve --service`; `enqueue` publishes without execution, and `queued` tasks retain native queue usage and replay contracts. YAML configuration format 2 adds declared observation clients with optional run storage, console sinks, local extension metadata and explicit final reports through the `/recipes` runtime. Successful execution is silent without declared outputs; `--json` explicitly requests a final report. Validate extensions without importing them. `recipes/parity.json` classifies public exports and options; new or changed fields require explicit classification; `scripts/recipe-schemas.mjs` generates editor schemas and `scripts/recipe-component-docs.mjs` generates component mappings and bilingual guides from those descriptors. Recipe speculation needs no experimental activation but requires native recovery for durability; recipe usage receipts preserve its cumulative accounting. Conflict integration closes the execution sandbox first and reports resolver usage separately.
